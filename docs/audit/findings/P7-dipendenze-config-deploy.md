## CRITICO
### P7-001 — Su un clone pulito, la suite e2e CANCELLA il database di SVILUPPO — **VERIFICATO DALL'ORCHESTRATORE**
Catena, ogni anello confermato:
1. `.env.test` **non è versionato** (`git ls-files` → solo `.env.example`, `apps/web-staff/.env.example`, `deploy/.env.prod.example`).
2. `apps/api/test/jest-setup-env.ts:6` → `if (fs.existsSync(envPath)) {…}` — se manca, **niente**: nessun errore, nessun warning.
3. `app.module.ts` → `ConfigModule.forRoot({ isGlobal: true })` **senza `envFilePath`** → `@nestjs/config` risolve `resolve(process.cwd(), '.env')`; con `pnpm --filter @coralyn/api` la cwd è `apps/api` → carica **`apps/api/.env`** → `DATABASE_URL` = **coralyn_dev**.
4. `PrismaService extends PrismaClient` senza `datasources` → legge `process.env.DATABASE_URL`.
5. Helper e2e: **11 `deleteMany({})` incondizionati** — `seed-map.ts:69-73` (umbrella, row, sector, umbrellaType, timeSlot), `seed-pricing.ts:87-92` (rate, pricing, season, packageEquipment, package, equipmentType).
6. `reset-dev.e2e-spec.ts` invoca `resetTenantData`, la cui unica guardia `assertResettableEnv` (`reset-dev.core.ts:22`) usa `/^coralyn_(dev|test)/i` → **accetta esplicitamente coralyn_dev**.
**Secondo vettore, attivo ANCHE quando `.env.test` esiste**: `jest-setup-env.ts:20` usa `if (!process.env[key])` → una `DATABASE_URL` esportata in shell **vince silenziosamente** sul file di test.
RADICE: il file che decide *contro quale database si distrugge* è gitignorato, senza template e senza validazione. La guardia esistente è stata scritta per proteggere dalla **produzione**, mentre il rischio reale in locale è il **dev**.
FIX (3 livelli): 1. versionare `.env.test.example` + rendere il caricamento **fatale** se il file manca; 2. **invertire la precedenza** (`process.env[key] = value` sempre: il file di test deve vincere sull'ambiente); 3. **asserzione hard sul nome DB** in `jest-setup-env.ts`: le e2e non devono *poter* puntare a un DB che non si chiami `coralyn_test`, qualunque env sia stata caricata.

## RADICI
